# aidc_load_15min_short — 模型测试思路说明

> 本文档说明 `config/aidc_load_15min_short/` 模型测试配置的设计思路。每路 41 个配置（A/B 合计 82）：baseline 9 + add_exogenous 8 + add_endogenous_cross_route 3 + add_endogenous_state 8 + add_decomposition 9 + add_ensemble 4。
>
> **2026-09-01/02 矩阵重建**：旧 US*/MS* 命名已全部废弃删除，现役命名为 `{model}_{strategy}[_{variant}].yaml`（如 `lgbm_direct.yaml`、`lgbm_recmo-decomp-stl96.yaml`）；全部配置为**点预测**（`probabilistic.mode: point`），不使用 quantile/CQR；模型融合统一收口在 `add_ensemble/` 组，特征基座 = add_exogenous。

## 1. 场景定位

| 项 | 值 | 说明 |
|---|---|---|
| 预测目标 | 15min 负荷（kW），A/B 两条供电路线独立建模 | `A/B_Loads_15min_mean_20251001_20260731.csv` |
| 预测跨度 | 16 步 = 调度时刻起未来 4h（超短期） | `horizon: 16`，以 freq 计步 |
| 调度语义 | 日内任意时刻滚动调度 | `schedule_mode: intraday`，`forecast_origin: 2026-07-31T14:00`，预测 14:00 → 17:45 |
| 回测几何 | history 1536 / train_window 1424 / 7 折 / 步长 16 | 以监督 origin steps 计：16 天历史、约 14.8 天训练窗、4h 步长滚动 |
| 评估口径 | 窗口级 MAPE/MAE，汇总用 **median**；附 Naive（昨日同时刻）对照 | R² 恒为负（4h 负荷近常数、方差极小），只看 MAPE/MAE |
| 预测模式 | 全部点预测 | `probabilistic.mode: point` |

> **与 daily/rolling 的差异**：horizon 缩短到 16 步（4h），历史与训练窗同步缩短；步长 16 步（4h）而非 1 天，7 个滑窗。跨场景对比 MAPE 时窗口覆盖时间范围不同，数值不完全可比。天气历史文件截断到调度前（`weather_15min_20250101_20260731T1345.csv`）。

## 2. 数据处理

| 环节 | 做法 | 为什么需要 |
|---|---|---|
| 上游清洗 | 源层 `aidc_load_5min` 异常检测（物理边界 + spike）后聚合为 15min | 派生频率不再重复清洗，避免口径漂移 |
| 目标值 | `value` 列直用，无缩放/去趋势 | 分解策略由 `add_decomposition` 组单独消融 |
| 训练期异常处理 | 无（未声明 `train_outlier`） | 源层已清洗，训练侧不二次处理 |
| 样本权重 | 无（未声明 `sample_weight`） | 新矩阵默认等权，衰减加权属后续消融项 |

## 3. 特征工程与分组

| 组 | 特征集（相对前一层的增量） | 数据通路 |
|---|---|---|
| `baseline` | 公共输入为 datetime 10 项 + 目标 lags [1,2,3,4,8,12,16,96,192,672]；direct/horizon/线性变体另有 rolling [16,96,672]×(mean/std/min/max) + diff [1,96,672] | 单源 `target_history`（A/B 单路文件） |
| `add_exogenous` | baseline + 气象 5 列（rt_tt2/cal_rh/rt_ssr/rt_ws10/rt_dt，`known_future`）+ 中国节假日（`is_holiday`/`next_holiday_days`，`chinese_holiday` generated source） | 天气严格三段路径；节假日 builtin generator |
| `add_endogenous_cross_route` | exogenous 特征集 + 对路负荷内生协变量（A 路目标 `A_load`、协变量 `B_load`，lags 同目标） | `forecasting_data/AB_Loads_*.csv` 合并宽表；协变量 `observed_past` + `provider: persistence` |
| `add_endogenous_state` | exogenous + 11 列 `state_*` 负荷状态特征（origin 冻结，lags 同目标） | `load_state_features/{A,B}_load_state_history.csv`；`observed_past` + `provider: persistence` |
| `add_decomposition` | exogenous + 目标分解（`linear` / `stl96` / `mstl96-672` 三变体） | 同 add_exogenous |
| `add_ensemble` | 成员特征基座 = add_exogenous（详见 §5） | 引用式成员，顶层 data 与成员一致 |

**天气严格信息集**：历史训练用实测（`weather_15min_20250101_20260731T1345.csv`，截断到调度前）；滑窗回测用 `weather_15min_backtest_proxy_20260101_20260731.csv`（ex-ante 代理，禁止测试期实测）；正式预测用 `weather_15min_future_proxy_20260731T1400_20260831.csv`。回测/预测天气均不含目标期实测，防止信息穿越。

**节假日**：`chinese_holiday` 为 builtin generated source（chinese-calendar 后端），走 canonical `known_future` 逐点精确匹配；覆盖范围外直接 RAISE，不静默降级。

> **short 场景 lag 注意**：lags 同时包含 1~16 步浅滞后和 96/192/672 步 safe-lag；浅滞后捕获 15min~4h 的近期自相关，日/周滞后提供周期参照，不能把整组误判为 safe-lag 配置。

## 4. 配置矩阵（每路 41 个）

| 配置 | 策略 | 估计器 | 定位 | 所在组 |
|---|---|---|---|---|
| `lgbm_direct` | direct | LightGBM | 主力基线 | baseline / add_exogenous / add_endogenous_cross_route / add_endogenous_state；分解组有对应变体 |
| `lgbm_direct_horizon` | direct + `single_model_horizon` + horizon_feature | LightGBM | horizon 作特征（H 模型 → 1 模型） | baseline / add_exogenous / add_endogenous_state |
| `lgbm_direct_pointwise` | direct + `single_model_horizon` + `align_to_target` | LightGBM | 逐点目标日对齐变体 | baseline / add_exogenous / add_endogenous_state |
| `lgbm_recmo` | recmo（chunk 4） | LightGBM | 4 步块输出对照 | baseline / add_exogenous / add_endogenous_state；分解组有对应变体 |
| `lgbm_mimo` | mimo | LightGBM | 16 步 horizon 一次输出 | 仅 add_endogenous_cross_route |
| `lgbm_recursive` | recursive | LightGBM | 递归对照 | baseline / add_exogenous / add_endogenous_cross_route / add_endogenous_state；分解组有对应变体 |
| `enet_direct` / `lasso_direct` / `ridge_direct` | direct | ElasticNet/Lasso/Ridge | 线性对照（feature_scaling minmax） | baseline/exogenous/state |
| `st_recursive` | recursive | SeasonalTemplate | 季节模板基线（工作日/周末 NNLS） | 仅 baseline |
| `lgbm_{direct,recmo,recursive}-decomp-{linear,stl96,mstl96-672}` | 三策略 × 三分解 | LightGBM | 分解消融 | 仅 add_decomposition |
| `lgbm_ensemble_{averaging,weighted,linear-blending,stacking}` | — | 引用式融合 | 四方法融合 | 仅 add_ensemble |

说明：`add_endogenous_cross_route` 组只有 3 个多变量 LightGBM 配置（direct/mimo/recursive）；`add_exogenous` 与 `add_endogenous_state` 均保留 3 个线性对照，跨路组不配置线性模型。

## 5. 模型融合（add_ensemble）

| 项 | 值 | 说明 |
|---|---|---|
| 成员 | `direct` → `../add_exogenous/lgbm_direct.yaml`；`recursive` → `../add_exogenous/lgbm_recursive.yaml` | 直接引用现役 add_exogenous 单模型，不维护重复的 `ensemble_members` 副本 |
| 方法 | averaging / weighted / linear_blending / stacking | 四种 canonical 融合方法 |
| OOF | train_window_steps 30 / fold_count 1 / stride 1 | 融合无泄漏质量证据 = OOF 融合评分 |
| 模式 | point | 与全矩阵一致 |

合约要点：成员 problem 字段与概率模式必须与顶层一致；成员 data source 必须是顶层 data 的相同/子集声明。融合引用的 direct/recursive 已显式声明所有 source 的 `series_id_cols`。

## 6. 结果目录与运行

```text
results/{pretrained_models,results_test,results_forecast}/<scenario_subpath>/<result_identity>/
```

- `scenario_subpath` = `aidc_load_15min_short/route_{A,B}/<group>`；
- 单模型 `result_identity` = `<strategy>-<model>-<scope>-k<K>-<fingerprint[:12]>`；ensemble = `ensemble-<method>-<scope>-k<K>-<fp[:12]>`；
- fingerprint 只取语义 payload，输出目录/并行度字段不参与。

单配置运行：改 `main.py::CONFIG_YAML` 指向目标 YAML 后

```bash
env -u PYTHONPATH UV_CACHE_DIR=.uv_cache uv run --no-sync python main.py
```

矩阵维护命令：`scripts/generate_load_15min_matrix.py` 默认只读校验 3 场景 × 2 路的 246 份配置；传 `--write-derived` 时只重写 24 个 `add_ensemble` 顶层 YAML，不覆盖基础单模型。
