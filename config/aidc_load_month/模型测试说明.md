# AIDC 日均负荷长跨度预测：模型测试说明

> `aidc_load_month` 是历史场景名。当前配置为 **日频 `1D`、一次预测 34 天的日均负荷功率**，不是月频、不是自然月预测，也不是月电量。本文以物理 YAML 与生产 loader 为准，文件名中的旧方法缩写不作为运行语义依据。

## 1. 数据和目录

| 路径 | 内容 |
|---|---|
| `route_A/`、`route_B/` | 每路 8 份主实验 YAML：4 个旧方法文件名 × point/quantile |
| `route_{A,B}/decomposition/` | 每路 5 份共享 Direct 点预测的目标分解对照 |
| `scripts/aggregate_{A,B}.yaml` | 从清洗后 5min 负荷生成日均值的离线配方 |
| `scripts/peak_valley_detect.yaml`、`scripts/periodicity_detect.yaml` | 峰谷及周期诊断配方，不是模型 YAML |
| `scripts/load_event_analysis.py` | 联合日频与 15min 数据的离线事件标签、特征和报告 |

模型只读取 `dataset/aidc_load_month/{A,B}_Loads_1day_mean_20251001_20260731.csv` 的 `time/value`，两路独立训练。当前两份输入各 **304 行**，覆盖 `2025-10-01～2026-07-31`，无空值。聚合配方指定 `source_freq: 5min`、`target_freq: 1D`、`method: mean`、`fill_method: linear`、`fill_weeks: 4`；日均值保留功率口径，不能与 `aidc_power_month` 的电量口径混用。离线填补值也会进入后续训练/评分，不能仅据“无空值”认定全部实测。

## 2. 配置矩阵与有效方法

共 **26 份物理模型 YAML**：18 份 point、8 份 quantile，全部为 LightGBM、Local 单目标、`target_adapter: independent`、`params: {}`。物理文件数不等于独立实验数：按 canonical fingerprint 去重后为 **20 个语义身份**。

| 文件名片段 | 当前有效方法 | 特征与预测方式 |
|---|---|---|
| `usmd` | Direct 独立模型 | 每个预测步独立建模，历史特征锚定预测原点 |
| `usmdp` | `direct-pointwise-horizon` | 共享模型，`align_to_target: true`，horizon 周期编码启用 |
| `usmdr` | Recursive | 当前 YAML 的 `strategy.name` 是 `recursive`，不是分块 RecMO |
| `usmr` | Recursive | 与同路、同 point/quantile 模式的 `usmdr` 语义相同 |

- `usmd` 与 Recursive：目标 lag 为 `1/2/3/4/5/6/7/14/28` 天；仅 `usmd` 另外启用 7/14/28 天 rolling 的 mean/std/min/max，以及 1/7/28 天 difference。
- `usmdp`：目标 lag 为 `34/35/42/49/56/63` 天，配合目标时间对齐，不能把最短 lag 改为 1 后仍假定无未来信息泄漏。
- 全部配置含 12 项日期特征；没有独立天气、计划、节假日 source 或跨路协变量。
- 主实验采用 linear 目标分解：`trend_degree: 1`、`trend_forecast: polynomial`、`trend_lookback: 28`；calendar normalization 和 scaling 均为 none。
- quantile 为 q10/q50/q90，点预测取 q50，交叉修复为 `median_preserving_isotonic` 并报告 raw crossing；没有 CQR 校准。q10～q90 为名义 80% 区间，不是已经实现 80% 覆盖率的承诺。

### 分解对照

五份配置都保持 `usmdp` 共享模型、特征、point 模式和回测几何，只改变目标分解。

| 文件后缀 | 设置 | 检验的问题 |
|---|---|---|
| `none` | 无分解 | 分解是否比直接拟合目标有收益 |
| `linear` | 一次趋势、多项式外推 | 近期线性趋势是否有帮助 |
| `quadratic` | `method: linear` 配合 `trend_degree: 2` | 二次趋势是否更好，是否放大远期外推误差 |
| `damped` | 一次趋势、阻尼外推，`damping: 0.98` | 抑制趋势持续外推是否更稳健 |
| `decomp_stl7` | robust STL，周期 7 天，`seasonal_cycles: 4` | 周周期分量是否改善预测 |

`decomposition/lgbm_usmdp_mean_linear.yaml` 与同路主目录 `lgbm_usmdp_mean.yaml` 具有相同 fingerprint，仅输出场景不同。`usmdr`/`usmr` 同模式文件连输出场景也相同，会定位同一结果身份。对比报表必须先按身份去重，不能把别名当独立模型，也不自动删除这些文件或旧结果。

## 3. 训练与回测口径

所有 YAML 的共同声明：

| 字段 | 当前值 | 含义 |
|---|---:|---|
| `problem.freq` / `problem.horizon` | `1D` / `34` | 每次连续预测 34 个日均值 |
| `validation.forecast_origin` | `2026-07-31T00:00:00` | 配置的已知数据截止点，不是自然月开始 |
| `horizon_mode` / `schedule_mode` | `fixed_steps` / `daily` | 日频固定步长任务，不走 calendar-month 调度 |
| `history_steps` | 304 | 旧 fixed-step 合同下的候选历史范围 |
| `train_window_steps` | 116 | 训练监督原点窗口，不是原始 116 天数据截断 |
| `fold_count` / `stride_steps` | 5 / 34 | 声明 5 折，每折推进 34 天 |

本场景尚未声明 `training_window`。不同方法的 lag 预热、标签跨度和监督设计不同，不能从 `116` 推导“所有模型只用相同 116 天原始数据”。实际折原点、训练样本数及预测时间以运行生成的 backtest metadata 为准；配置可解析不证明每折数据和完整生命周期已经通过。

> 公平比较先对齐路线、日期、预测步、目标变换和评分掩码。`usmd`/`usmdp`/Recursive 同时改变了方法和特征设计，属于方案对比，不是严格单因素方法消融。

## 4. 检查、运行与产物

从仓库根执行；环境规则见 [AGENTS.md](../../AGENTS.md)，参数合同见 [config/README.md](../README.md)。

```bash
# 静态配置检查，不拟合模型
env -u PYTHONPATH .venv/bin/python scripts/check_model_configs.py 'config/aidc_load_month/**/*.yaml'
# 单份历史回测；会训练并写正式 results，获准后再执行
env -u PYTHONPATH .venv/bin/python run.py --config-yaml config/aidc_load_month/route_A/lgbm_usmd_mean.yaml --backtest-only
```

`--backtest-only` 不生成 final fit、bundle 或末次预测；不带此开关走完整生命周期，不能用旧的 `is_testing/is_forecasting` 字段控制。常规产物位于 `results/results_test/aidc_load_month/<route>[/decomposition]/<identity>/backtest_only/`，包括逐窗/逐 horizon 评分、canonical long `cv_plot_df.csv`、metadata、总图和 `windows_results/`；结果身份规则见 [model_forecasting/README.md](../../model_forecasting/README.md)。

评估同时看 MAE、RMSE、MAPE、与季节 Naive 的差异及远期 horizon 衰减；概率模型另看 pinball loss、覆盖率、宽度和 crossing。点预测与概率预测分别比较，不把 q50 称为均值，也不以旧文件名中的 `mean` 推断统计输出。

## 5. 离线诊断与当前边界

`load_event_analysis.py` 生成 `event_label_features/` 下的逐日特征、事件 CSV、总览图和日频分析报告。`feat_*` 是 trailing 特征，`xf_*` 是日内聚合，`xr_*` 为跨路线统计；日内统计和同日对侧负荷只能在该日信息已知后使用。部分 `lbl_*` 依赖居中检测/事后事件划分，只供离线分析，不能直接作为未来已知特征。当前模型 YAML **没有消费这些诊断产物**。

该脚本迁入 `scripts/` 后，`PROJECT_ROOT = Path(__file__).resolve().parents[2]` 实际指向仓库的 `config/`，会寻找不存在的 `config/dataset/aidc_load_month/…`。因此这里只记录入口及用途，不给出可直接生成报告的承诺；修复路径属于后续代码任务。`--help` 可解析不等于业务入口可执行。

文档核验已通过全部 26 份配置的静态 checker，并核对输入行数和重复身份；没有执行正式模型、重建数据或验证预测效果。旧结果只有在 fingerprint、数据版本、窗口与当前配置一致后才能用于本矩阵结论。
