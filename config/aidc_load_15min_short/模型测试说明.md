# aidc_load_15min_short — 模型测试思路说明

> **V4 当前态（2026-10-09 收敛为 LightGBM 单估计器）**：A/B 每路 81 份配置，其中 baseline 9、add_exogenous 27、add_endogenous_cross_route 9、add_endogenous_state 9、add_decomposition 27；另有 route_AB/add_endogenous_joint 9 份。场景合计 **171**，全部为 LightGBM 单模型。
>
> 2026-10-09 起矩阵收敛为单一估计器 LightGBM：其余 8 个估计器（ST/Ridge/Lasso/ElasticNet/XGBoost/CatBoost/RandomForest/HistGradientBoosting）的配置，以及依赖 ST/Ridge baseline 成员的 `add_ensemble`（每路 12 份 Latin 融合）全部移出活动集，内容由 Git 保留。单模型组为 9 策略完整展开；外生组再乘 holiday/weather/holiday+weather 三变体，分解组再乘 linear/MSTL(96,672)/STL(96) 三变体。

## V4 当前配置合同

- 目标：A/B 两路 15min 负荷；`horizon=16`，`forecast_origin=2026-07-31T14:00:00`，`schedule_mode=intraday`。
- 外生、跨路、状态和联合目标组采用`training_window: {kind: rolling, history_steps: 2112}`、`forecast_window: {start: after_origin}`、`refit_every: 1`；先在原始窗内预热并筛选安全标签，再选择训练原点。baseline、分解组同样使用 `training_window`（rolling），但不叠加 forecast_window/refit_every/origin_sampling，窗长按策略分化为 2112（direct/dirmo/mimo）与 2111（其余策略）。
- Direct独立模型、MIMO、DIRMO、DirRec、DirRecMO保留全部安全原点；Direct共享horizon的两种布局、Recursive、RecMO按`stride_steps: 96`及正式forecast_origin锚点采样。该规则对同组全部估计器一致，不改变每日发报步长与31折声明。
- forecast_origin是最后已知点，目标从下一点开始；当前正式原点对应2026-07-31 14:15至18:00，不是从14:00开始。新窗口支持final fit/bundle链路，但不代表已经完成正式模型或部署验收。新旧训练口径未统一的组不得直接作单因素精度归因；公共合同见[config说明](../README.md)。
- 模型：LightGBM（唯一估计器；其余估计器配置已移出活动集）。
- 策略/布局：Direct pointwise、Direct pointwise+horizon 周期编码、Direct、Recursive、DirRec、DirMO、RecMO、DirRecMO、MIMO；MO chunk=4。
- 基础特征：通用 target lags `[1,2,3,4,8,12,16,96,192,672]`、rolling `[16,96,672]` × mean/std/min/max、expanding mean/std、10 项 datetime；不保留 difference。
- safe-lag 例外：两种 pointwise 的 target lags 只保留 `[16,96,192,672]`，避免 Direct 访问原点之后的 target；observed-past lags 仍由 persistence provider 支持。
- 外生变体：holiday、weather、holiday+weather；当前天气仅声明history_path，通过inference_columns区分训练实测列与历史预测预报列，不再使用独立backtest/future路径。真正未来运行需补齐future阶段资产，不能把历史回放当作在线预报证据。
- 分解三变体全部保留；MSTL(96,672) 的训练窗仅约 2.1 个周周期，配置覆盖不代表统计合理性。
- Ensemble：`add_ensemble` 组已随非 LightGBM 成员一并移出活动集（2026-10-09）；ModelEnsemble 链路本身保留，后续如需融合以 LightGBM 成员重建。
- 配置与设计门禁、合成运行测试不等于正式矩阵的模型效果验收；配置更新不自动重跑业务训练、回测或融合OOF，也不迁移旧结果。

## 历史：V3 收敛矩阵（已被 V4 替代）

## 1. 场景定位

| 项 | 值 | 说明 |
|---|---|---|
| 预测目标 | 15min 负荷（kW），A/B 两条供电路线独立建模 | `A/B_Loads_15min_mean_20251001_20260731.csv` |
| 预测跨度 | 16 步 = 调度时刻起未来 4h（超短期） | `horizon: 16`，以 freq 计步 |
| 调度语义 | 日内任意时刻滚动调度 | `schedule_mode: intraday`，`forecast_origin: 2026-07-31T14:00`，预测 14:00 → 17:45 |
| 回测几何 | history 5072 / train_window 1424 / 31 折 / 步长 96 | 约 52.8 天可用历史、14.8 天训练窗；每天固定 10:00 origin 预测 4h，共 31 日 |
| 评估口径 | 窗口级 MAPE/MAE，汇总用 **median**；附 Naive（昨日同时刻）对照 | R² 恒为负（4h 负荷近常数、方差极小），只看 MAPE/MAE |
| 预测模式 | 全部点预测 | `probabilistic.mode: point` |

> **与 daily/rolling 的差异**：horizon 缩短到 16 步（4h），训练窗约 14.8 天；回测改为日步长，使 31 个窗口覆盖一个月而非连续 28 小时。跨场景的 Horizon 不同，MAPE 仍不能直接等价比较。

## 2. 数据处理

| 环节 | 做法 | 为什么需要 |
|---|---|---|
| 上游清洗 | 源层 `aidc_load_5min` 异常检测（物理边界 + spike）后聚合为 15min | 派生频率不再重复清洗，避免口径漂移 |
| 目标值 | `value` 列直用，无缩放/去趋势 | 分解策略由 `add_decomposition` 组单独消融 |
| 训练期异常处理 | 无（未声明 `train_outlier`） | 源层已清洗，训练侧不二次处理 |
| 样本权重 | 无（未声明 `sample_weight`） | 新矩阵默认等权，衰减加权属后续消融项 |

## 3. 特征工程与分组

| 组 | 特征集（相对前一层的增量） | 数据通路 |
|---|---|---|
| `baseline` | LightGBM × 9 策略（Direct pointwise / Direct pointwise+horizon / Direct / Recursive / DirRec / DirMO / RecMO / DirRecMO / MIMO），统一使用 datetime 10 项 + target lags [1,2,3,4,8,12,16,96,192,672] + rolling [16,96,672]×(mean/std/min/max) + expanding(mean/std)，无 difference/分解 | 单源 `target_history`（A/B 单路文件） |
| `add_exogenous` | baseline 9 策略 × holiday/weather/holiday+weather 三变体 = 27 份；气象 5 列 + 中国节假日 | 天气严格三段路径；节假日 builtin generator |
| `add_endogenous_cross_route` | exogenous 特征集 + 对路负荷内生协变量（A 路目标 `A_load`、协变量 `B_load`，lags 同目标），9 策略 | `forecasting_data/AB_Loads_*.csv` 合并宽表；协变量 `observed_past` + `provider: persistence` |
| `add_endogenous_state` | exogenous + 10 列纯本路 `state_*` 状态特征，9 策略 | 删除 `state_route_diff_pct`；浅 lag 越过 origin 时显式 persistence |
| `add_decomposition` | exogenous + 9 策略 × linear/MSTL(96,672)/STL(96) 三变体 = 27 份 | 训练窗仅约 2.1 个周周期，MSTL 配置覆盖不代表统计合理性 |
| `route_AB/add_endogenous_joint` | A/B 同时作为 target，K=2，9 策略 | 真正联合输出，不使用 peer persistence |

**天气严格信息集**：历史训练用实测（`weather_15min_20250101_20260731T1345.csv`，截断到调度前）；滑窗回测用 `weather_15min_backtest_proxy_20260101_20260731.csv`（ex-ante 代理，禁止测试期实测）；正式预测用 `weather_15min_future_proxy_20260731T1400_20260831.csv`。回测/预测天气均不含目标期实测，防止信息穿越。

**节假日**：`chinese_holiday` 为 builtin generated source（chinese-calendar 后端），走 canonical `known_future` 逐点精确匹配；覆盖范围外直接 RAISE，不静默降级。

> **short 场景 lag 注意**：lags 同时包含 1~16 步浅滞后和 96/192/672 步 safe-lag；浅滞后捕获 15min~4h 的近期自相关，日/周滞后提供周期参照，不能把整组误判为 safe-lag 配置。

## 4. 配置矩阵（A/B 每路 81 个 + 联合 9 个，全部 LightGBM）

| 配置 | 策略 | 定位 | 所在组 |
|---|---|---|---|
| `lgbm_{direct-pointwise,direct-pointwise-horizon,direct,recursive,dirrec,dirmo,recmo,dirrecmo,mimo}` | 9 策略全覆盖（MO chunk=4） | LightGBM 主力基线全策略展开 | baseline；cross_route / state 组同构 9 份 |
| `lgbm_<9策略>_{holiday,weather,holiday-weather}` | 9 策略 × 3 外生变体 = 27 | 外生来源消融 | add_exogenous |
| `lgbm_<9策略>_decomp-{linear,mstl96-672,stl96}` | 9 策略 × 3 分解变体 = 27 | 分解方法与策略交互 | add_decomposition |
| `route_AB/lgbm_<9策略>` | K=2 联合目标，9 策略 | A/B 真正联合预测 | add_endogenous_joint |

说明：cross-route 是单目标 + peer observed-past 对照；`route_AB` 才是 K=2。估计器维度已收敛为 LightGBM。

## 5. 模型融合（已移出活动集）

`add_ensemble` 原 3 个 Latin 成员组 × 4 方法（每路 12 份）依赖 baseline 的 ST/Ridge 成员；2026-10-09 矩阵收敛为 LightGBM 单估计器后整组移出活动集，内容从 Git 历史溯源。ModelEnsemble 代码链路保留，后续如需融合应以 LightGBM 成员重建引用式配置。

## 6. 结果目录与运行

```text
results/{pretrained_models,results_test,results_forecast}/<scenario_subpath>/<result_identity>/
```

- `scenario_subpath` = `aidc_load_15min_short/route_{A,B}/<group>` 或 `aidc_load_15min_short/route_AB/add_endogenous_joint`；
- 单模型 `result_identity` = `<strategy>-<model>-<scope>-k<K>-<fingerprint[:12]>`；
- fingerprint 只取语义 payload，输出目录/并行度字段不参与。

单配置运行（`run.py` 无默认配置，必须显式指定 YAML）：

```bash
env -u PYTHONPATH .venv/bin/python run.py --config-yaml config/aidc_load_15min_short/<route>/<group>/<model>.yaml
```

V3 当时的矩阵维护入口为 `--write-derived`；该参数及 304 份矩阵已被 V4 `--write` 合同替代。2026-10-09 收敛为 LightGBM 单估计器后，`--write` 只重建三个场景共 **513** 份单模型 YAML（每场景 171 份）。
