# ESS 储能站用电预测：模型测试说明

本文件统一原 README 与测试设计说明，覆盖数据、实验矩阵、信息可得性、策略特征和结果判定。`ess_selfuse_load` 是储能站自身用电负荷；实际 PCS 功率和未来 PCS 计划是解释变量，不是预测目标。当前规范为 canonical schema 2，旧文件名缩写仅用来定位配置。

## 1. 目录与配置计数

A/B 两路结构对称，各有 **41 个实验入口**，合计 **82 个**；另有每路 2 个 `ensemble_members/` 成员文件，所以递归扫描共 **86 份模型 YAML**。82 个入口中，68 个 quantile、14 个 point；连成员文件计为 70 个 quantile、16 个 point。

| 实验组 | 入口/路 | 测试内容 | 重要对照条件 |
|---|---:|---|---|
| `baseline` | 5 | Direct、共享 Direct、RecMO、Recursive、引用式融合 | 仅目标历史，无日期、天气和目标分解 |
| `add_decomposition` | 12 | 4 个单模型方法 × linear/STL/MSTL | 无日期；不是融合成员的分解实验 |
| `add_endogenous_actual_strategy` | 7 | 实际 PCS 历史、horizon、persistence/auxiliary、融合 | point；带日期特征；目标列改为 `ess_power` |
| `add_exogenous_weather` | 4 | 六项天气与日期特征 | 无分解；不属于“只加天气”的单因素对照 |
| `add_exogenous_plan_strategy` | 4 | 显式未来 PCS 计划 | 无日期，但保留 linear 分解 |
| `add_exogenous_weather_plan_strategy` | 4 | 天气＋日期＋计划 | 无分解；与纯计划组同时存在分解差异 |
| `add_strategy_features` | 5 | C5 完整 50 列策略特征＋CQR | 无日期、天气、分解或融合 |

模型 YAML 位于 `route_{A,B}/<组>/`；离线准备入口、策略特征实现与配方均在 `scripts/`，不再位于场景根目录。天气适配的输入、输出和命令见 [scripts/README.md](scripts/README.md)。

## 2. 文件名与实际预测方法

| 旧缩写 | 当前配置语义 | 简单理解 |
|---|---|---|
| USMD / MSMD | `direct`、`independent_models` | 对各预测步分别拟合 |
| USMDP | `single_model_horizon`、`align_to_target: true` | 共享模型，使用目标时刻对齐的 safe-lag；当前 horizon 周期编码启用 |
| MSMD-horizon / USMD-horizon | `single_model_horizon`、`align_to_target: false` | 共享模型，历史冻结在原点并追加 horizon 周期编码 |
| USMDR / MSMDR | `recmo`、`output_chunk_length: 96` | 每次输出 96 步，再回填预测，直到完成 288 步 |
| USMR / MSMR | `recursive` | 逐步预测与回填 |
| USBR / MSBR | 引用式 `linear_blending` Ensemble | 融合 Direct 与独立 Recursive 成员，不是第八种预测策略 |

USMDP 的有效结果标签为 `direct-pointwise-horizon`，不能依据旧文件名把它等同于禁用 horizon 的 pointwise。baseline 与实际 PCS 组各自的 blend YAML 都通过 `config_ref` 引用同组 Direct 和 `ensemble_members/` 下的 Recursive。

**融合当前存在运行阻塞**：成员已声明 `training_window`，而 `model_ensemble/runtime.py` 仍明确拒绝带显式时间窗口的成员。静态 checker 通过不代表这 4 个融合入口能够训练；须先修复该合同不一致，不能删掉窗口字段绕过，更不能把融合从实验矩阵移除。

## 3. 数据与训练窗口

- 普通目标：`dataset/aidc_ess_selfuse_load/forecasting_data/{A,B}_GateEnergys_5min_20251001_20260728_remove_outlier.csv`，目标列 `value`。
- 实际 PCS 组：同目录 `{A,B}_ESS_PCS_merged_5min_20251001_20260728.csv`，目标 `ess_power`，历史协变量 `pcs_power`。
- 全部模型频率 `5min`、H=288、Local；配置截止点 `2026-07-28T23:55:00`，声明 `fold_count: 5`、`stride_steps: 288`。外层 `history_steps` 已退役，按截止点向前选最近完整折，不改变训练窗口。
- 常规目标 lag 为 288/576/864/1152/1440/1728/2016，亦即 1～7 天。Direct 的 rolling/difference、共享模型的对齐和 RecMO 的回填是方法差异，不能统一描述为相同特征矩阵。

当前全部配置已声明原始训练窗口，不能写“所有方法统一训练 29 天”：

| 物理配置范围 | 当前声明 | 数量（含成员） |
|---|---|---:|
| 按窗口长度分组（含成员与融合顶层） | `training_window: {kind: rolling, history_steps: 16704}` | 22 |
| 按窗口长度分组（含成员与融合顶层） | `training_window: {kind: rolling, history_steps: 10655}` | 56 |
| 按窗口长度分组（含成员与融合顶层） | `training_window: {kind: rolling, history_steps: 10656}` | 8 |

`training_window.history_steps` 是原始历史点数；旧 `train_window_steps` 和外层 `history_steps` 已退役，不能与内层混用。没有配置声明 `forecast_window: next_day`；实际预测时刻与折几何由运行合同解析。各方法比较必须同时披露窗口，不把“相同 fold_count”解释成“相同训练数据”。

## 4. 外生信息集与防泄漏

### 实际 PCS

`pcs_power` 是 `observed_past`，必须通过显式 provider 处理不可见的后续值。普通配置为 persistence；`*_aux.yaml` 为 auxiliary，对照只放在 Recursive/RecMO。预测期的实际 PCS 不能假装已知计划；带 PCS 的组同时改变目标字段、日期特征及预测模式，与纯目标 quantile baseline 不构成干净的单因素比较。

### 天气

天气统一使用六项原始量，不构造天气统计派生：

| 变量 | 训练列 | 历史测试预测列 |
|---|---|---|
| 温度 | `rt_tt2` | `pred_tt2` |
| 相对湿度 | `cal_rh` | `pred_rh` |
| 辐射 | `rt_ssr` | `pred_ssrd` |
| 风速 | `rt_ws10` | `pred_ws10` |
| 气压 | `rt_ps` | `pred_ps` |
| 降雨 | `rt_rain` | `pred_rain` |

活动 source 使用 `exogenous_weather_raw/weather_history_5min_20250101_20260831.csv`，训练与历史预测均读 history，预测阶段通过 `inference_columns` 取 pred_；不再使用旧四天气量、旧截止日期或 weather future 文件。`availability: forecast_origin` 是配置的可得性假设，不是供应商真实发布时间证据。共享离线修补、ERA5 替代与派生血缘保留在 repair/metadata，不冒充在线实测。

### 未来 PCS 计划

计划是普通 `data.sources` 中名为 `pcs_plan` 的 file source，角色 `known_future`；**不再使用旧 `custom_features/future_strategy/strict_information_set` 字段**。当前声明 `availability: column`、`available_at_col: available_at`，分别配置历史计划与未来计划路径，列名均为 `pcs_plan`。

`scripts/split_strategy_plan.py` 将目标日计划的 `available_at` 派生为前一日 23:55。这是业务假设，不是原始发布记录；真实版本/发布时间可用后应透传真实事实。目标网格缺点或发布晚于 fold origin 均不能靠取未来实际值补齐。

## 5. 分解、分位数与 CQR

分解组为 4 个单模型方法各配 linear、robust STL(288)、robust MSTL(288,2016)；后两者分别表示日周期与日/周周期。无分解对照在 baseline；`trend_lookback: 28` 是配置点数，不可在 5min 场景误写为 28 天。目标变换在各折训练内拟合，不能用全测试期趋势或季节分量作已知特征。

quantile 使用 q10/q50/q90，点预测取 q50；`median_preserving_isotonic` 修复 crossing，raw crossing 同时报告。只有 C5 组显式启用 CQR：基础区间 `q10_q90`、`target_coverage: 0.9`、`calibration_windows: 5`、`min_windows: 3`、`min_scores: 30`。基础 q10～q90 区间名义覆盖率为 80%，CQR 目标为 90%，二者不能混写；历史窗口不足时读取校准审计，不宣称已经完成校准。

## 6. C5 策略特征准备

入口为 `scripts/build_strategy_features.py`，配方为 `scripts/strategy_features.yaml`，实现位于 `scripts/strategy_features/`。数据流水线按 C1→C2→C3→C5 累积，但模型只保留 C5 完整特征配置。

| 层 | 增量列数 | 内容与信息边界 |
|---|---:|---|
| C1 | 10 | ESS/实际 PCS 日滞后、上一已完成周期画像、readiness |
| C2 | 21 | 已知 PCS 计划、方向、充放电时长/能量、切换与首时刻编码 |
| C3 | 11 | 计划距离与新颖度、相似日/近期稳健模板、gate 与 readiness |
| C5 | 8 | D−1 联合聚类 one-hot、中心距离、rare 与 readiness |
| 合计 | 50 | 不包含时间索引 `time` |

- 自然日为 00:00～23:55；调度周期为 22:00～次日 21:55，不能混用两类边界。
- `as_of_time` 为历史事实截止；未来 288 点必须是完整、唯一、递增的 5min 自然日网格，关键模型列全部有限。
- 联合聚类固定 reference 为 `2025-11-01～2026-06-27`；各视图独立 StandardScaler＋PCA（解释率至少 90%），K=2～5 按 silhouette 选择 KMeans，小类标记 rare。预测 D 日只用 D−1 分配，不把当天事后类别送入未来。
- `contracts.py` 维护模型列、未来必需列与泄漏黑名单；`lag_feature_ready/template_feature_ready` 等是显式资格标记，不以缺失值代替状态。
- 未来不得带目标或当前实际 PCS；历史质量缺口保留审计。补齐未来关键列不等于已证明全部历史信息都能在线获得。

从仓库根检查参数（不计算或落盘）：

```bash
env -u PYTHONPATH .venv/bin/python -m config.aidc_ess_selfuse_load.scripts.build_strategy_features --help
```

获准后，完整计算但不写入使用 `--validate-only`；写入改用 `--force`。两种模式互斥，均显式传入 `--config config/aidc_ess_selfuse_load/scripts/strategy_features.yaml --data-root dataset/aidc_ess_selfuse_load`。采用模块入口并指定 data-root，是因为脚本迁移后默认根仍错误落在 `config/dataset/aidc_ess_selfuse_load`；不把默认路径假装有效。此处没有重建策略特征。

每路输出到 `dataset/aidc_ess_selfuse_load/forecasting_data/strategy_features/`：

- `model_features_history_{A,B}.csv`、`model_features_future_{A,B}.csv`。
- `audit/calendar_day_quality_{A,B}.csv`、`dispatch_cycle_summary_{A,B}.csv`、`similar_day_matches_{A,B}.csv`、`feature_build_audit_{A,B}.json`。
- `audit/joint_cluster_assignments_{A,B}_fit-20260627.csv` 与 `artifacts/joint_cluster_{A,B}_fit-20260627.joblib`；回测 reference artifact 不与未来重新拟合的 artifact 混用。

## 7. 执行与结果判定

运行环境见 [AGENTS.md](../../AGENTS.md)，模型入口要求显式 canonical YAML。单模型只做历史回测时必须传 `--backtest-only`；不传该参数会走完整生命周期，旧 `is_testing/is_forecasting` 已不是合法开关。融合入口不适用单模型 backtest-only 模式，且必须先解决上文成员窗口阻塞。

```bash
# 静态 checker；通过不代表融合运行门禁或数据覆盖已通过
env -u PYTHONPATH .venv/bin/python scripts/check_model_configs.py 'config/aidc_ess_selfuse_load/**/*.yaml'
# 单模型回测示例；会训练并写正式结果，需运行授权
env -u PYTHONPATH .venv/bin/python run.py --config-yaml config/aidc_ess_selfuse_load/route_A/baseline/lgbm_usmd_prob_mean.yaml --backtest-only
```

结果按 `results/results_test/aidc_ess_selfuse_load/<路线>/<实验组>/<identity>/` 隔离，backtest-only 另有同名子目录；检查 `run_state.json`、fingerprint、backtest/result metadata，再读取 `test_scores_df.csv`、`test_scores_horizon_df.csv`、`cv_plot_df.csv`、`test_prediction.png` 和 `windows_results/`。完整生命周期另有模型与预测目录；不能声称所有配置天然只写测试产物。canonical long schema 和结果身份见 [预测产物说明](../../model_forecasting/README.md)。

比较按 A/B 路、共同测试日期、同目标口径、同训练窗口配对；同时报告 MAPE、MAE、RMSE、有效点比例与 Naive。概率组另看 pinball、覆盖率、区间宽度、crossing 和 CQR 状态。原实验采用“A/B 同向、median ΔMAPE ≥ 0.005”的人工判据；若继续采用，应明确 Δ 为基线减候选、MAPE 用小数值，且这不是 YAML 中自动执行的门禁。

相关测试为 `tests/test_ess_strategy_*.py`；分组与执行方式见 [tests/README.md](../../tests/README.md)。当前静态 checker 覆盖 86/86，但没有运行正式模型、评估效果、构建 final bundle 或重算策略资产。静态通过与上述运行阻塞并不矛盾。
