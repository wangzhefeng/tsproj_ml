# aidc_load_15min_rolling — 模型测试思路说明

> **V4 当前态（2026-09-03）**：A/B 每路 741 份配置，其中 baseline 81、add_exogenous 243、add_endogenous_cross_route 81、add_endogenous_state 81、add_decomposition 243、add_ensemble 12；另有 route_AB/add_endogenous_joint 81 份。场景合计 **1,563**（1,539 单模型 + 24 Ensemble）。
>
> 六个单模型组完整展开 9 模型 × 9 策略；外生组再乘 holiday/weather/holiday+weather 三变体，分解组再乘 linear/MSTL(96,672)/STL(96) 三变体。`add_ensemble` 独立保留三组 Latin-square × 四方法，不参与全因子乘法。

## V4 当前配置合同

- 目标：A/B 两路 15min 负荷；`horizon=96`，`forecast_origin=2026-07-31T14:00:00`，`schedule_mode=intraday`。
- 模型：ST、Ridge、Lasso、ElasticNet、LightGBM、XGBoost、CatBoost、RandomForest、HistGradientBoosting。
- 策略/布局：Direct pointwise、Direct pointwise+horizon 周期编码、Direct、Recursive、DirRec、DirMO、RecMO、DirRecMO、MIMO；MO chunk=24。
- 基础特征：target lags `[96,192,288,384,480,576,672]`、rolling `[96,192,384,672]` × mean/std/min/max、expanding mean/std、10 项 datetime；不保留 difference。
- 外生变体：holiday、weather、holiday+weather；天气历史截止 13:45，future 从 14:00 开始，并使用独立 backtest proxy。
- 内生变体：cross-route peer lags（persistence provider）、本路 10 状态列 lags、A/B K=2 joint target。
- Ensemble：每路 12 份，直接引用 baseline 的 ST/LightGBM/Ridge × Direct/Recursive/MIMO 九个成员；无 `ensemble_members/`。
- 本轮只做配置生成和静态合同验证，不执行训练、回测、预测或融合 OOF。

## 历史：V3 收敛矩阵（已被 V4 替代）

## 1. 场景定位

| 项 | 值 | 说明 |
|---|---|---|
| 预测目标 | 15min 负荷（kW），A/B 两条供电路线独立建模 | `A/B_Loads_15min_mean_20251001_20260731.csv` |
| 预测跨度 | 96 步 = 调度时刻起未来 24h | `horizon: 96`，以 freq 计步 |
| 调度语义 | 日内任意时刻滚动调度 | `schedule_mode: intraday`，`forecast_origin: 2026-07-31T14:00`，预测 14:00 → 次日 13:45 |
| 回测几何 | history 6336 / train_window 2784 / 31 折 / 步长 96 | 以监督 origin steps 计：66 天可用历史、29 天训练窗、固定 14:00 的连续 31 个日窗 |
| 评估口径 | 窗口级 MAPE/MAE，汇总用 **median**；附 Naive（昨日同时刻）对照 | R² 不适用（日内近常数段） |
| 预测模式 | 全部点预测 | `probabilistic.mode: point` |

> **与 daily 场景的唯一运行语义差异**：`schedule_mode: intraday`——预测起点是调度时刻（14:00）而非次日 00:00，训练窗口右端同步保留日内时刻。两者模型矩阵相同，构成「日界 vs 日内滚动」对照。天气历史文件相应截断到调度前。

## 2. 数据处理

| 环节 | 做法 | 为什么需要 |
|---|---|---|
| 上游清洗 | 源层 `aidc_load_5min` 异常检测（物理边界 + spike）后聚合为 15min | 派生频率不再重复清洗，避免口径漂移 |
| 目标值 | `value` 列直用，无缩放/去趋势 | 分解策略由 `add_decomposition` 组单独消融 |
| 训练期异常处理 | 无（未声明 `train_outlier`） | 源层已清洗，训练侧不二次处理 |
| 样本权重 | 无（未声明 `sample_weight`） | 新矩阵默认等权，衰减加权属后续消融项 |

## 3. 特征工程与分组

| 组 | 特征集（相对前一层的增量） | 数据通路 |
|---|---|---|
| `baseline` | 融合候选池 9 份 = ST/LightGBM/Ridge × Direct/Recursive/MIMO，统一使用 datetime 10 项 + target lags [96,192,288,384,480,576,672] + rolling [96,192,384,672]×(mean/std/min/max) + expanding(mean/std)，无 difference/分解；另保留 enet_direct、lgbm_direct_horizon、lgbm_direct_pointwise、lgbm_recmo 四个既有控制 | 单源 `target_history`（A/B 单路文件）；Ridge 仅额外使用 MinMax 缩放，ST 实际只消费 lag 与 day-of-week |
| `add_exogenous` | 完整版 = baseline + 气象 5 列 + 中国节假日；另设 weather-only / holiday-only Direct 控制 | 天气严格三段路径；节假日 builtin generator；完整基座覆盖七策略与 XGB |
| `add_endogenous_cross_route` | exogenous 特征集 + 对路负荷内生协变量（A 路目标 `A_load`、协变量 `B_load`，lags 同目标） | `forecasting_data/AB_Loads_*.csv` 合并宽表；协变量 `observed_past` + `provider: persistence` |
| `add_endogenous_state` | exogenous + 10 列纯本路 `state_*` 状态特征；全量 Direct 与训练窗内 SelectKBest 对照 | 删除 `state_route_diff_pct`；`observed_past` + persistence |
| `add_decomposition` | exogenous + Direct×linear/STL/MSTL、RecMO×MSTL、Recursive×MSTL | 同 add_exogenous，避免完整笛卡尔积 |
| `add_ensemble` | 3 个 Latin 成员组 × 4 方法；每组恰含 ST/LightGBM/Ridge 与 Direct/Recursive/MIMO 各一次 | 直接引用 baseline 九个普通成员；顶层 data 与成员同为单一 target_history |
| `route_AB/add_endogenous_joint` | A/B 两列同时作为 target，K=2 MIMO / Recursive | 复用 AB 宽表与完整外生信息集 |

**天气严格信息集**：历史训练用实测（`weather_15min_20250101_20260731T1345.csv`，截断到调度前）；滑窗回测用 `weather_15min_backtest_proxy_20260101_20260731.csv`（ex-ante 代理，禁止测试期实测）；正式预测用 `weather_15min_future_proxy_20260731T1400_20260831.csv`。回测/预测天气均不含目标期实测，防止信息穿越。

**节假日**：`chinese_holiday` 为 builtin generated source（chinese-calendar 后端），走 canonical `known_future` 逐点精确匹配；覆盖范围外直接 RAISE，不静默降级。

## 4. 配置矩阵（A/B 每路 50 个 + 联合 2 个）

| 配置 | 策略 | 估计器 | 定位 | 所在组 |
|---|---|---|---|---|
| `{st,lgbm,ridge}_{direct,recursive,mimo}` | Direct / Recursive / MIMO | ST / LightGBM / Ridge | 九个固定-profile 融合候选，三组 Latin 轮换 | baseline |
| `lgbm_direct` | direct | LightGBM | 主力基线 | baseline / add_exogenous / add_endogenous_cross_route / add_endogenous_state；分解组有对应变体 |
| `lgbm_direct_horizon` | direct + `single_model_horizon` + horizon_feature | LightGBM | horizon 作特征（H 模型 → 1 模型） | baseline / add_exogenous |
| `lgbm_direct_pointwise` | direct + `single_model_horizon` + `align_to_target` | LightGBM | 逐点目标日对齐变体 | baseline / add_exogenous |
| `lgbm_{mimo,recmo,dirrec,dirmo,dirrecmo}` | 五种中间策略（MO chunk 24） | LightGBM | 与 Direct/Recursive 合成七策略覆盖 | 完整 add_exogenous；cross-route 另保留 MIMO |
| `lgbm_recursive` | recursive | LightGBM | 递归对照 | baseline / add_exogenous / add_endogenous_cross_route / add_endogenous_state；分解组有对应变体 |
| `enet_direct` | direct | ElasticNet | 既有稀疏线性控制，不进入 Latin 融合池 | baseline |
| `xgb_direct` | direct | XGBoost | 完整外生特征下的异构树模型对照，不进入本轮 baseline Latin 融合池 | 完整 add_exogenous |
| `lgbm_direct_weather_only` / `holiday_only` | direct | LightGBM | 外生来源独立归因 | add_exogenous |
| `lgbm_direct_selected` | direct | LightGBM | 状态全量 vs SelectKBest（最多 80） | add_endogenous_state |
| `st_recursive` | recursive | SeasonalTemplate | 季节模板基线（工作日/周末 NNLS） | 仅 baseline |
| 五个 `lgbm_*-decomp-*` | 3 个 Direct 分解 + 2 个 MSTL 策略交互 | LightGBM | 分解实现与关键交互 | 仅 add_decomposition |
| `ensemble_latin-{a,b,c}_{averaging,weighted,linear-blending,stacking}` | — | 引用式融合 | 三个平衡成员组 × 四方法 | 仅 add_ensemble |
| `route_AB/{lgbm_mimo,lgbm_recursive}` | K=2 | LightGBM | 真正联合预测 | add_endogenous_joint |

说明：cross-route 是单目标 + peer observed-past 对照；`route_AB` 才是两目标联合输出。矩阵不再把所有模型、策略和特征做笛卡尔积。

## 5. 模型融合（add_ensemble）

| 项 | 值 | 说明 |
|---|---|---|
| Latin A 成员 | ST Recursive + LGBM MIMO + Ridge Direct | 自然优势组合 |
| Latin B 成员 | ST Direct + LGBM Recursive + Ridge MIMO | 第一次轮换 |
| Latin C 成员 | ST MIMO + LGBM Direct + Ridge Recursive | 第二次轮换；三组合计覆盖全部 9 个 model×strategy 配对 |
| 方法 | averaging / weighted / linear_blending / stacking | 每组均应用四种方法，共 12 个 Ensemble/路 |
| OOF | train_window_steps 2784 / fold_count 5 / stride 96 | 与成员正式训练窗一致，5 个日步长无泄漏 OOF |
| 模式 | point | 与全矩阵一致 |

合约要点：成员 problem、data 与 point 模式必须一致；每个 Latin 组内四种方法共享相同成员顺序和 OOF 几何。九个成员是普通 baseline 配置，ST 只消费 lag 与 day-of-week，Ridge 单独使用 MinMax 缩放。

## 6. 结果目录与运行

```text
results/{pretrained_models,results_test,results_forecast}/<scenario_subpath>/<result_identity>/
```

- `scenario_subpath` = `aidc_load_15min_rolling/route_{A,B}/<group>` 或 `aidc_load_15min_rolling/route_AB/add_endogenous_joint`；
- 单模型 `result_identity` = `<strategy>-<model>-<scope>-k<K>-<fingerprint[:12]>`；ensemble = `ensemble-<method>-<scope>-k<K>-<fp[:12]>`；
- fingerprint 只取语义 payload，输出目录/并行度字段不参与。

单配置运行（`main.py` 无默认配置，必须显式指定 YAML）：

```bash
env -u PYTHONPATH .venv/bin/python main.py --config-yaml config/aidc_load_15min_rolling/<route>/<group>/<model>.yaml
```

V3 当时的矩阵维护入口为 `--write-derived`；该参数及 304 份矩阵已被本文置顶的 V4 `--write` / 4,689 份合同替代。
