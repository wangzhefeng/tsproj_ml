# aidc_load_15min_short — 模型测试思路说明

> 本文档说明该场景下 `config/aidc_load_15min_short/` 模型测试配置的设计思路（不含 `ensemble/`、`params_tuning/`）。每路 53 个、A/B 合计 106 个：baseline 10 + add_exogenous_weather_date 8 + add_decomposition 27 + add_load_state 8。

## 1. 场景定位

| 项 | 值 | 说明 |
|---|---|---|
| 预测目标 | 15min 负荷（kW），A/B 两条供电路线独立建模 | `A/B_Loads_15min_mean_20251001_20260731.csv` |
| 预测跨度 | 16 步 = 调度时刻起未来 4h（超短期） | `schedule_mode: intraday`，保留调度时刻 |
| 调度语义 | 日内任意时刻滚动调度 | `now_time: 2026-07-31 14:00`（调度时刻本身，预测 14:00 → 18:00） |
| 回测窗口 | 历史 30 天 / 训练窗 14 天 / 步长 1 天 | 17 个滑窗（`(30−14)/1+1`） |
| 评估口径 | 窗口级 MAPE/MAE，汇总用 **median**；附 Naive（昨日同时刻）对照 | R² 恒为负（4h 负荷近常数、方差极小），只看 MAPE/MAE |

> **与 daily/rolling 的差异**：horizon 缩短到 16 步（4h），历史与训练窗同步缩短（30/14 天 vs 60/30 天）。注意滑窗数 17 < 31，跨场景对比 MAPE 时窗口覆盖时间范围不同，数值不完全可比。

## 2. 数据处理

| 环节 | 做法 | 为什么需要 |
|---|---|---|
| 上游清洗 | 源层 `aidc_load_5min` 异常检测（物理边界 + spike）后聚合为 15min | 派生频率不再重复清洗，避免口径漂移 |
| 目标值 | `value` 列直用，无缩放/去趋势 | 由 `add_decomposition` 组单独消融分解策略 |
| 训练期异常处理 | `enable_train_outlier_handling: false` | 源层已清洗，训练侧不二次处理 |
| 样本权重 | 时间衰减 `decay_halflife_days: 60` | 近期样本权重更高；USMD/USMDR 多输出 quantile 路径按 sklearn 限制安全跳过 |

## 3. 特征工程

| 特征类 | 内容 | 适用范围 |
|---|---|---|
| 滞后特征 | `lags: [1,2,3,4,8,12,16,96,192,672]`（近邻 15min~4h + 1/2/7 天同刻） | 除 USMDP 外所有配置；近邻滞后是超短期核心信息源 |
| 高级特征 | rolling `[16,96,672]` + diff `[1,96,672]`（≤ max(lags)） | USMD/USBR 开启；USMR/USMDR/USMDP 关闭 |
| 日历特征 | hour/minute/day/day_of_week/week_of_year/month/days_in_month/quarter/day_of_year/year | 全部配置 |
| 天气特征 | `rt_tt2/cal_rh/rt_ssr/ws10`，严格信息集 | 仅 add_exogenous_weather_date / add_decomposition / add_load_state 组 |
| 负荷状态特征 | 源表 15 列，配置选择 11 列 `state_*`；剔除与基线 rolling 精确重复的 24h/7d mean/std，使用 `freeze_last_observation + end_of_period` | 仅 add_load_state 组 |

> **核心认识**：超短期场景的 lag 设计与日级场景本质不同——`[1,2,3,4,8,12,16]` 近邻滞后（15min~4h）捕获短期自相关，是 4h horizon 的主力特征；日周期滞后 `[96,192,672]` 退居辅助。天气对 4h 超短期的边际价值预期低于日级场景（日内天气变化慢），消融组用于验证这一假设。

**天气严格信息集**：历史训练用实测（actual）；滑窗回测用 `weather_15min_backtest_proxy_*.csv`（proxy，禁止使用测试期实测）；正式预测用 `weather_15min_future_proxy_*.csv`（proxy）。回测/预测天气均不含目标期实测，防止信息穿越。

## 4. 模型设置（baseline 组 10 配置）

| 配置 | 模型/方法 | 预测类型 | 定位 |
|---|---|---|---|
| `lgbm_usmd_prob_mean_conformal` | LightGBM / USMD（直接多步） | quantile(0.1/0.5/0.9) + CQR | 主力基线 |
| `lgbm_usmd_prob_mean_horizon_conformal` | LightGBM / USMD + horizon_feature | 同上 | horizon 作特征的变体（训练 H×→1×） |
| `lgbm_usmdp_prob_mean_conformal` | LightGBM / USMDP（逐点） | 同上 | 纯日历模板（无 lag），对照 |
| `lgbm_usmdr_prob_mean_conformal` | LightGBM / USMDR（直接+递归） | 同上 | 混合策略对照 |
| `lgbm_usmr_prob_mean_conformal` | LightGBM / USMR（递归） | 同上 | 递归策略对照（4h horizon 递归误差累积风险低） |
| `lgbm_usbr_prob_mean_conformal` | LightGBM / USBR（Direct+Recursive blend） | 同上 | ridge_stacking 学融合权重 |
| `enet_usmd_mean` / `lasso_usmd_mean` / `ridge_usmd_mean` | ElasticNet/Lasso/Ridge / USMD | point | 线性对照（`scale_features: true`） |
| `st_usmr_mean` | SeasonalTemplate / USMR | point | 季节模板基线（工作日/周末分组 NNLS） |

所有 LightGBM 配置均开启 **CQR conformal 校准**（最近 5 窗口校准集，α=0.1）；`model_params` 为空 = 用工厂默认值；`window_parallel_workers: 8`。

## 5. 消融组设计

| 组 | 相对 baseline 的变化 | 回答的问题 |
|---|---|---|
| `add_exogenous_weather_date`（8） | + 严格信息集天气特征 | 天气对 4h 超短期是否有增益 |
| `add_decomposition`（27） | weather-date 基础上分别使用 `linear` / `stl96` / `mstl[96,672]` | 目标分解是否优于端到端 |
| `add_load_state`（8） | weather-date 同名配置 + 11 列 origin-frozen load_state；`decomposition_method: none` | 负荷状态是否在天气基线上提供独立增量 |

> **核心认识**：目标分解与 load_state 是以 weather-date 为共同基线的两条正交消融，不再层层叠加。`add_load_state` 与 weather-date 同名配置除输出隔离和 custom state 外保持一致（包括 conformal），不含不消费状态的 st 或不进入天气组的 USBR。

## 6. 结果目录命名

```
setting = {model}-{data_stem}-{method_code}-{window_days}[-quantile]{setting_suffix}
```

本场景 `window_days=14`，setting 形如 `lightgbm-A_Loads_15min_mean_20251001_20260731-usmd-14-quantile-conformal`；同组内各配置按 suffix 隔离（`-decomp-linear` / `-decomp-stl96` / `-horizon-conformal` 等）。conformal 覆盖率须读 `results_forecast/.../prediction.csv`（测试段 `cv_plot_df.csv` 中 `predict_q*` 是未校准原值）。
