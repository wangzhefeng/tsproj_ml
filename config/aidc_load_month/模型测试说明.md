# AIDC 日均负荷长跨度预测：模型测试说明

> `aidc_load_month` 是历史场景名。当前配置为 **日频 `1D`、每月 25 号发报、按自然月预测下月整月（28～31 天，按当月实际天数）的日均负荷功率**，不是月频点、不是月电量。本文以物理 YAML 与生产 loader 为准；文件名自 2026-11-10 起与 canonical 方法名一致（`direct`/`direct-pointwise`/`direct-pointwise-horizon`/`recursive`/`mimo`/`dirrec`/`recmo`/`dirmo`/`dirrecmo`），point 文件无后缀、quantile 文件带 `_prob` 后缀，旧 `usm*` 缩写与 `_mean` 后缀已退役。

## 1. 数据和目录

| 路径 | 内容 |
|---|---|
| `route_{A,B}/baseline_point/` | 每路 9 份 point 主实验 YAML：9 种方法（direct/direct-pointwise/direct-pointwise-horizon/recursive/mimo/dirrec/recmo/dirmo/dirrecmo） |
| `route_{A,B}/baseline_prob/` | 每路 9 份 quantile 主实验 YAML，与 `baseline_point/` 方法一一配对 |
| `route_{A,B}/decomposition/` | 每路 10 份 point：dph × 6 档分解（none/linear/quadratic/damped/stl7/mstl730）+ direct/recursive × {none, stl7} 方法交叉；分解消融不做 quantile |
| `scripts/aggregate_{A,B}.yaml` | 从清洗后 5min 负荷生成日均值的离线配方 |
| `scripts/peak_valley_detect.yaml`、`scripts/periodicity_detect.yaml` | 峰谷及周期诊断配方，不是模型 YAML |
| `scripts/load_event_analysis.py` | 联合日频与 15min 数据的离线事件标签、特征和报告 |

模型只读取 `dataset/aidc_load_month/{A,B}_Loads_1day_mean_20251001_20260731.csv` 的 `time/value`，两路独立训练。当前两份输入各 **304 行**，覆盖 `2025-10-01～2026-07-31`，无空值。聚合配方指定 `source_freq: 5min`、`target_freq: 1D`、`method: mean`、`fill_method: linear`、`fill_weeks: 4`；日均值保留功率口径，不能与 `aidc_power_month` 的电量口径混用。离线填补值也会进入后续训练/评分，不能仅据“无空值”认定全部实测。

## 2. 配置矩阵与有效方法

共 **56 份物理模型 YAML**（两路各 28）：主实验 36 份（18 point + 18 quantile，9 种方法全部配对），分解对照 20 份 point。全部为 LightGBM、Local 单目标、`target_adapter: independent`、`params.n_estimators: 100`。物理文件数不等于独立实验数：按 canonical fingerprint 去重后为 **54 个语义身份**，2 份别名文件（point 的 `decomp_linear` 与主实验重复，两路各 1 份）。2026-11-10 起文件名与 canonical 方法名一致；`usmdr` 与 `usmr` 原为同 fingerprint 同输出场景的纯别名，更名时合并为 `recursive` 一份（各删除 2 份冗余文件）。本次目录分类与 identity 增加 `point`/`prob` 不改变 fingerprint；旧结果目录保留，不按新身份自动迁移。

| 文件名片段 | 方法 | 特征与预测方式 |
|---|---|---|
| `direct` | Direct 独立模型 | 每个预测步独立建模，历史特征锚定预测原点 |
| `direct-pointwise` | `direct-pointwise` | 与 `direct-pointwise-horizon` 唯一差异为关闭 horizon 特征，构成严格单因素消融 |
| `direct-pointwise-horizon` | `direct-pointwise-horizon` | 共享模型，`align_to_target: true`，horizon 周期编码启用 |
| `recursive` | Recursive | 原 `usmr`（与 `usmdr` 同身份） |
| `mimo` | MIMO | 单模型一次输出整月；特征与 `direct` 同设计（lag 1–28 + rolling/difference/expanding） |
| `dirrec` | DirRec | 逐 horizon 独立模型 + 消费前序预测；特征与 Recursive 同设计 |
| `recmo`/`dirmo`/`dirrecmo` | 块方法（B=2） | 特征与 Recursive 同设计（`dirmo` 另带 independent_models Direct 块）；quantile 依赖 `median_path` 块间传播（`dirmo` 无递归依赖，逐块直接出分位） |

- 原点锚定族（`direct`/`mimo`/Recursive/`dirrec`/`recmo`/`dirmo`/`dirrecmo` 及对应分解对照）：目标 lag 为 `1/2/3/4/5/6/7/14/28` 天，rolling 窗口为 `7/14/28/60/90` 天（mean/std/min/max），difference 周期为 `1/7/28` 天。60/90 天长窗补充固定窗水平与波动信息，避免只有 expanding 全历史统计。
- 目标对齐族（`direct-pointwise`/`direct-pointwise-horizon` 及其分解对照）：目标 lag 为 `37/38/42/49/56/63` 天，difference 周期为 `37/42` 天。25 号发报时最远目标在原点后 36 天（2026-03～07 折），最短 lag/difference 周期必须不小于最大跨度，否则会把对齐特征落到原点之后的未知值上。rolling 锚点跟随目标时刻，目标对齐下无法保证不越过原点，因此该族不声明 rolling，只保留安全 lag、difference 与 expanding。
- 全部配置含 12 项日期特征，并启用 expanding（`value` 全历史 mean/std）；均有 `chinese_holiday` generated source，以 known-future `is_holiday`/`next_holiday_days` 入模。没有独立天气、计划 source 或跨路协变量。
- 块方法合同边界：`output_chunk_length: 2`，`problem.horizon` 声明为 36。当前回测窗口每折 runner 跨度 [34,36,36,36,36] 与 2026-08 正式预测跨度 36 均可被 2 整除；未来奇数跨度月份（如 12 月 25 号发报预测 1 月，跨度 37）会按合同 RAISE。块长语义改造（声明块数、按折自适应）是后续候选合同变更，不是当前配置能力。
- 主实验采用 linear 目标分解：`trend_degree: 1`、`trend_forecast: polynomial`、`trend_lookback: 28`；calendar normalization 和 scaling 均为 none。
- quantile 为 q10/q50/q90，点预测取 q50，交叉修复为 `median_preserving_isotonic` 并报告 raw crossing；没有 CQR 校准。q10～q90 为名义 80% 区间，不是已经实现 80% 覆盖率的承诺。

### 分解对照

分解消融仅 point 模式（quantile × 分解交叉经一轮验证后按裁决删除，其结论由主实验 `_prob` 与分解 point 差异间接推断）。dph 方法下覆盖全部 6 档分解，检验分解对点预测的影响；另设方法交叉组：`direct`/`recursive` × {none, stl7}——`none` 检验主配置「默认 linear 分解」这一决策本身，`stl7` 检验周期分解对非 dph 方法是否有效。分解是目标级变换（顺序 `calendar normalization → decomposition → scaling`），与策略正交；`recursive × 分解` 在 calendar_month 下经本场景实跑验证（power_month、ess 场景另有 direct/recursive/recmo × 分解先例）。

| 文件后缀 | 设置 | 检验的问题 |
|---|---|---|
| `none` | 无分解 | 分解是否比直接拟合目标有收益 |
| `linear` | 一次趋势、多项式外推 | 近期线性趋势是否有帮助 |
| `quadratic` | `method: linear` 配合 `trend_degree: 2` | 二次趋势是否更好，是否放大远期外推误差 |
| `damped` | 一次趋势、阻尼外推，`damping: 0.98` | 抑制趋势持续外推是否更稳健 |
| `decomp_stl7` | robust STL，周期 7 天，`seasonal_cycles: 4` | 周周期分量是否改善预测 |
| `decomp_mstl730` | robust MSTL，周期 [7, 30] 天 | 在周周期之上叠加近似月周期是否有增量 |

`decomposition/…direct-pointwise-horizon_decomp_linear.yaml` 与同路 `baseline_point/…direct-pointwise-horizon.yaml` 具有相同 fingerprint，仅输出场景不同；两路各有一对这样的别名。对比报表必须先按身份去重，不能把别名当独立模型，也不自动删除这些文件或旧结果。

## 3. 训练与回测口径

所有 YAML 的共同声明：

| 字段 | 当前值 | 含义 |
|---|---:|---|
| `problem.freq` / `problem.horizon` | `1D` / `37` | horizon 是最大 runner 跨度声明（12 月 25 号发报预测 31 天次月 = 6+31）；每折实际跨度动态解析 |
| `horizon_mode` / `schedule_mode` | `calendar_month` / `daily` | 自然月调度，每折预测一个完整自然月，H 按当月实际天数 |
| `origin_day` | `25` | 每折原点为目标月开始前一个月的 25 号；缺省（不声明）则是月末前一天 |
| `validation.forecast_origin` | `2026-07-31T00:00:00` | 配置的已知数据截止点；生产按当月 25 号数据截止调用 |
| `train_window_days` | `120` | 每折使用截至原点（含原点）的最近 120 个日频原始点，预热在窗内 |
| `fold_count` / `stride_months` | 5 / 1 | 声明 5 折，每折推进一个自然月；2026-03～07 各一折 |

本场景使用 calendar-month 独立训练窗合同；`training_window`、`stride_steps`、外层 `history_steps`、旧 `train_window_steps` 均拒绝。25 号原点与月首之间有 4～7 天（随上月天数变化）gap：runner 每折按 `lead-1+当月天数` 覆盖全跨度（2026-03～07 折为 34/36/36/36/36），递归方法穿越 gap 天，评分切片只保留目标自然月（gap 天不进任何指标）；训练标签末端不越过折原点。2026-02 折因原点（2026-01-25）前仅 117 天不足 120 被几何层剔除，属合同行为不是缺数据告警。seasonal-naive 对照回看完整跨度（`lead-1+当月天数`），保证全部落在原点之前。最终预测（非 backtest-only）保持 `origin+1..origin+37` 全跨度输出，月度交付按当月行筛选。实际折原点、训练样本数及预测时间以运行生成的 backtest metadata 为准；配置可解析不证明每折数据和完整生命周期已经通过。

> 公平比较先对齐路线、日期、预测步、目标变换和评分掩码。`direct`/`direct-pointwise-horizon`/Recursive 同时改变了方法和特征设计，属于方案对比，不是严格单因素方法消融。

## 4. 检查、运行与产物

从仓库根执行；环境规则见 [AGENTS.md](../../AGENTS.md)，参数合同见 [config/README.md](../README.md)。

```bash
# 静态配置检查，不拟合模型
env -u PYTHONPATH .venv/bin/python scripts/check_model_configs.py 'config/aidc_load_month/**/*.yaml'
# 单份历史回测；会训练并写正式 results，获准后再执行
env -u PYTHONPATH .venv/bin/python run.py --config-yaml config/aidc_load_month/route_A/baseline_point/lgbm_direct.yaml --backtest-only
```

`--backtest-only` 不生成 final fit、bundle 或末次预测；不带此开关走完整生命周期，不能用旧的 `is_testing/is_forecasting` 字段控制。常规产物位于 `results/results_test/aidc_load_month/<route>/<baseline_point|baseline_prob|decomposition>/<identity>/backtest_only/`，配置目录与三类 results 根下的场景子路径一致；包括逐窗/逐 horizon 评分、canonical long `cv_plot_df.csv`、metadata、总图和 `windows_results/`。identity 在指纹前显式包含 `point` 或 `prob`，详见 [model_forecasting/README.md](../../model_forecasting/README.md)。

评估同时看 MAE、RMSE、MAPE、与季节 Naive 的差异及远期 horizon 衰减；概率模型另看 pinball loss、覆盖率、宽度和 crossing。点预测与概率预测分别比较：point 文件无后缀、quantile 文件带 `_prob`，quantile 点预测取 q50，不得据文件名称其为均值。

## 5. 离线诊断与当前边界

`load_event_analysis.py` 生成 `event_label_features/` 下的逐日特征、事件 CSV、总览图和日频分析报告。`feat_*` 是 trailing 特征，`xf_*` 是日内聚合，`xr_*` 为跨路线统计；日内统计和同日对侧负荷只能在该日信息已知后使用。部分 `lbl_*` 依赖居中检测/事后事件划分，只供离线分析，不能直接作为未来已知特征。当前模型 YAML **没有消费这些诊断产物**。

该脚本的 `PROJECT_ROOT = Path(__file__).resolve().parents[3]` 已随 2026-10-10 场景迁移提交（`323b2405`）修正为仓库根，此前文档记载的 `parents[2]` 指向 `config/` 的问题不复存在；2026-11-09 双路全量实跑通过，可按上方用法直接生成报告与产物。

文档核验已通过全部配置的静态 checker：2026-11-09 迁移 calendar_month+origin_day 后 26/26 通过；2026-11-10 扩展策略与分解覆盖、canonical 更名去后缀、补齐块方法 quantile与分解交叉后峰值 76/76；同日按裁决删除分解目录全部 quantile 交叉后 56/56 通过（54 个语义身份）。扩展当日每个新家族各实跑一份 `--backtest-only` 通过，块方法逐折跨度 [34,36,36,36,36] 均满足 B=2 整除，块方法 quantile 的 `median_path` 块间传播经 dirrecmo 实跑验证，recursive × 分解在 calendar_month 下经 `recursive_decomp_stl7` 实跑验证。随后统一设置 `n_estimators: 100`、接入 `chinese_holiday`、补齐递归族 rolling/difference、对齐族 difference(37/42) 及原点族 60/90 天长窗后，checker 再次 56/56 通过；`recursive`、`direct-pointwise-horizon`、`dirrecmo_prob`、dph `decomp_stl7` 与 `direct` 五份代表配置实跑通过，节假日生成器对 2025-10-01～2026-09-06 的 341 天覆盖核验通过。`load_event_analysis.py` 已于 2026-11-09 双路实跑重建诊断产物；calendar-month origin_day 合同由 `tests/test_calendar_month_origin_day.py` 覆盖。语义 fingerprint 可用于核对新旧结果是否同源，但本次可读身份及场景目录变化不会自动迁移旧结果；fixed_steps 与扩展前的旧结果 fingerprint 不同，只有在数据版本、窗口与当前配置一致后才能用于本矩阵结论。
